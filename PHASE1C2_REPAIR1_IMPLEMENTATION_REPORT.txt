1. Repair reason and result

The Phase 1C2 manual validation failed because Edit -> Linear -> Plot Channel
duplicated the existing Interface Settings color-channel concept and placed the
new control in the wrong location.

The Plot Channel submenu, its R/G/B/RGB QActions, its QActionGroup, its signal,
and its checked-state mirror have been completely removed. The existing Edit ->
Linear menu and its Single Image / Image Series numbering-mode actions remain.
Detection Scope, Detection Numbering, Interface, Enable Camera, and all other
existing menus and shortcuts remain in place.

The final Interface Settings -> Detection -> Concentration order is:

- Detection color channel: R / G / B
- Linear plot channel: R / G / B / RGB
- RGB calculation precision
- RGB display decimals
- Concentration display decimals

No new tab, group box, menu, toolbar action, dialog, .ui file, or generated UI
file was added or modified. Both selectors use the existing QFormLayout row
geometry, so they share the existing spacing, width, and height rules.

2. Configuration authority and migration

interface_config.py now recognizes the independent key linear_plot_channel.
Its valid values are exactly R, G, B, and RGB. Its new-install and Restore
Defaults value is B.

color_channel remains independent and continues to accept only R, G, and B.
RGB was not added to its valid values. The Detection worker continues to read
settings["color_channel"], use SampleResult.concentration_for(color_channel),
and render Con.R, Con.G, or Con.B through the existing formal path.

The pure merge_settings_overrides function owns backward compatibility:

- if an old overrides document lacks linear_plot_channel, the validated load
  snapshot inherits its R/G/B color_channel value;
- loading this legacy document performs no write;
- an explicitly present but invalid linear_plot_channel falls back to B without
  changing a valid Detection color_channel;
- other schema validation and unknown-field handling remain unchanged.

save_settings remains the only Interface Settings persistence path and retains
QSaveFile atomic publication outside the project tree. Clicking OK validates
and saves both keys together. Clicking Cancel neither saves nor changes either
runtime channel. The existing Settings saved message remains.

3. Runtime integration and independence

DetectMain retains one Linear Plot runtime authority:

self._linear_plot_channel_mode

Its construction snapshot now reads initial_settings["linear_plot_channel"],
with B as the defensive failure fallback. It no longer normally initializes
from Detection color_channel.

The strict _set_linear_plot_channel_mode method:

- accepts only exact R/G/B/RGB strings;
- writes no setting or file;
- reads no QAction state;
- changes no Detection setting;
- redraws exactly once when an active RegressionSet exists;
- redraws zero times when no active RegressionSet exists;
- reads no clock and changes no Linear or Detection time;
- triggers no regression, detection, worker, model, or Camera path.

InterfaceSettingsDialog exposes only its final validated and successfully saved
settings snapshot. DetectWindow calls the Plot setter once, and only after the
dialog returns Accepted. Detection color_channel remains handled by the
existing saved-settings/worker load path and is never passed to the Plot setter.

Projection, renderer, Detection overlays, calibration and detection revision
gates, selected image order, Save Linear current-view behavior, XLSX schemas,
transactions, callbacks, numbering, concentrations, timing, worker, model, and
Camera code were not modified.
